# 查询本机知识与经验

## When to use

- 自动触发：开始重要、复杂或重复工作前，已有项目位置、文件总结、历史决定、稳定规则、失败护栏或类似经验可能影响当前判断。
- 自动触发：消息或上下文出现项目、路径、文件名，以及“之前、以前、类似、规则、历史、为什么这么做”等回溯线索。
- 自动触发：当前结论可能与旧结论、既有职责或既有做法冲突，需要先查再判断。
- 用户自然问“之前这个构建错误怎么处理的？”“这个项目在哪？”“这份 README 以前总结过吗？”“这个项目相关的经验有哪些？”或“这个概念以前怎么定义的？”。
- 不用于写入、纠正、归档或删除任何数据。知识目录未初始化时，只友好说明暂时没有可查询内容。

## Workflow

1. **理解问题。** 结合消息、最近上下文、当前目录、已选项目和附件提取 1–4 个自然短语，判断用户要找项目、文件、项目历史、知识还是经验。检查：业务目标应唯一；不通过则只问一个自然问题，例如“我找到了两个可能对象：当前工作区项目和归档项目，你指哪个？”。
2. **按层定位。** 项目先查 `indexes/projects.md`、`indexes/files.md` 和项目 README/inventory；文件整理再查唯一资料集台账与独立结果；项目历史查相关 summary。稳定事实先读 `knowledge/current/INDEX.md`，做法或故障先读 `experience/current/INDEX.md`，只用 index 的 title、scope、tags、source 简写、复现提示和特异概括缩到少量候选，再打开默认 1–3 篇正文。复现只表示同类模式后来有独立证据再次发生，在相关性相近时供解释参考，不能覆盖 scope、source、时点或现场。纠错追溯或用户明确询问历史时，才定向读取 archive INDEX。检查：只硬排除与当前项目、工作区或客户明确矛盾的 scope；tag 默认只加分。不通过则回到原文件，不跨资料集猜测。
3. **筛选并复核。** 索引缺失、断链或与目录条目不一致时，只读降级为该目录有限 frontmatter 扫描，并自然说明“认知导航需要维护”；不得重建或写回。先过滤再维护最多 50 个元数据候选；按精确 path/source/id、当前 scope、精确标题/别名/文件名、tag、短语命中数和词法顺序排序。默认读 1–3 篇正文，冲突比较最多 5 篇；认知正文合计不超过 64 KiB，原始证据摘录不超过 32 KiB。检查：文件台账指向唯一结果且结果 source 等于原路径，current 的 source/scope/learned_at 与本次问题相符；不通过则只保留已核实线索并说明缺口。
4. **用自然语言回答。** 区分索引导航、单文件结果、项目综合、知识、经验、原文件历史事实和当前现场；易变事实必须现场复核。检查：每个结论都有本次读回证据且未超预算；不通过则说“找到一些线索，但证据还不完整，下面只列已核实部分”。零命中固定说“暂未找到相关记录”；只有本次确实用索引内已有别名改写过一次，才补“也按已有别名查过”。知识目录不可读说“本机知识目录暂时无法读取”。

## Tools and data sources

- 数据根是 `~/.agent-knowledge/` 下的 Markdown、CSV、原文件路径和现场状态；四个 K/E 目录先读各自 `INDEX.md`，`archive/` 默认不读。
- 使用宿主原生只读文件 API、固定字符串搜索和安全的 Markdown/CSV 解析器；不硬依赖某个命令、语言运行时或网络。
- 长文件只读相关标题、段落或切片；多 source 只加载支撑本次结论的来源，但回答列出全部 source。

## Gotchas

- 索引命中、exact source、结构校验或 current 存在都不代表事实正确；原文件、当前代码、配置和运行现场优先。
- 不把 broad OR 的前 50 个结果当候选集，也不因 tag 缺失丢弃相关条目；零命中或过宽时只用现有索引中的别名改写一次。
- owner 缺失、重叠或 legacy 字段无法解释时，说明导航不完整并回原文件；不要要求用户提供 id、scope、source 或 tags。
- INDEX 只用于缩小候选，不是事实来源；索引失配时始终只读降级，不能自行修复。
- 始终只读，不记录访问次数或普通使用次数，不自动触发任何写入；INDEX 中已有复现提示也不能单独证明结论正确。
